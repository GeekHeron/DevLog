实际改动

共 3 处，全部在 public/site-nav.css。远端提交 8f20d39 只含这一个文件（+17 / −1）。

/* 1) 新增：nav 自身成为 flex 容器并顶到最右 */
+ header.site-header nav,
+ header.site-header .nav-links {
+     display: flex;
+     align-items: center;
+     margin-left: auto;
+     flex: 0 0 auto;
+ }

/* 2) 右侧内边距收窄 50px -> 24px */
  header.site-header {
-     padding: 20px 50px;
+     padding: 20px 24px 20px 50px;
  }

/* 3) 移动端抽屉内抵消桌面规则（必须） */
  @media (max-width: 768px) {
      header.site-header nav {
          position: fixed; /* 全屏浮层 */
+         margin-left: 0;
+         flex: 0 0 auto;
      }
  }

为什么改一个文件就够

1. 公共表在同等特异性下稳定胜出。遍历 86 个构建产物确认：82 / 82 页的内联 <style> 都排在 site-nav.css 之后被解析 —— 也就是公共表后加载。所以新规则能覆盖全站 7 种内联变体，无需逐页改动。
2. 原来的不一致有 7 种来源。按顶层规则把 84 页分桶，得到 7 种布局签名：26 页 .nav-links{display:flex}、25 页只有 .logo、15 页多一条 header{}、9 页 padding 是 30px 50px、7 页完全没有顶层规则、另加 2 个单页变体。差异集中在 padding 与是否声明 .nav-links，不是 DOM 结构 —— 所有页面的 header 标记完全一致。
3. 「菜单在右上角」本来就是设计。桌面端汉堡按钮 display:none，header 只剩 logo 与 nav 两个可见子项，justify-content: space-between 必然把 nav 顶到右边。本次做的是让这个「右」在全站一致，并且真正贴近边缘。
